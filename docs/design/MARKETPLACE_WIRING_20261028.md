# Marketplace receipt authority and both client adapters

2026-10-28. Overall goal remains active. This checkpoint follows `marketplace-observation-20261028.md`; it does not authorize production or claim actual device/two-client acceptance.

## Canonical authority contract

Authorized conversation detail now supplies an opaque, versioned receipt authority digest. It constrains the authenticated actor, conversation identity, buyer/seller side, explicitly requested store/company context, and the current canonical grant. Personal-store ownership, workspace-store link identity, company ownership/revision and membership identity/role/revision distinguish those grants. Active-account revisions also invalidate observations across suspension/restoration. Invalid or exhausted counters yield no receipt context while leaving ordinary authorized conversation access available. Neither this digest nor any client actor ID grants access.

The digest reuses the existing canonical account/company/member revisions maintained by sourcing-authority triggers. `companies.ts`, superadmin lifecycle/bulk/ownership and merge controls, monitoring user transitions, verifier suspension, deletion request/cancellation and creation wrappers retain those triggers. New/re-invited memberships and new store links have new document IDs. Current store/conversation identity fields are created by canonical creation paths; the store settings mutation does not transfer ownership or relink stores. No new schema, counter backfill or migration ran. Future authority writers must preserve lasting revision or replacement identity.

Bound read/delivery transactions reconcile the full digest against current authority before message or notification writes. Existing actor/sharing-generation checks, explicit IDs, full foreign-batch validation and the 100-ID bound remain. Legacy API calls remain compatible, but the new Consumer and standalone adapters do not fall back to those unbound calls when context is absent, revoked or belongs to another actor.

## Consumer and standalone

The checked shared receipt module now supplies a Marketplace-specific transport adapter. Its local observer identity includes the complete authority digest and store context. The numeric observer epoch is unused for Marketplace authority; the durable digest in that identity handles grant changes. A command captured for an old grant cannot be dispatched through a replacement transport ref. Frozen actor/consent/context data and exact IDs go to Marketplace endpoints, never personal thread receipt endpoints.

Consumer's existing personal observation hook now shares its focus, visibility, measured geometry, resize, dwell and cancellation implementation with Marketplace. The Marketplace page no longer acknowledges loaded history or performs broad read acknowledgement on scroll/latest navigation. Only eligible visible incoming messages become read after active dwell; received IDs are delivered in bounded batches with retry. Explicit sender side excludes other employees' messages from incoming observations.

Standalone Commerce supplies the same checked adapter to MessageList. It uses the existing FlashList viewport geometry, active/focused/connectivity handling and shared observer retry. Marketplace keeps its canonical inline per-message receipt projection, rather than invoking personal receipt-state queries. Other staff's store-side messages and restricted/deleted rows are excluded from incoming observations. The actual Commerce screen has focused wiring checks for current, old-backend, revoked and stale-account contexts. The native list remains mounted across receipt preparation and grant changes.
