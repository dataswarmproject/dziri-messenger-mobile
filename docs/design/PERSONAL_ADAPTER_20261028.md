## Behavior

Consumer and standalone DM now capture the same immutable thread/actor/authority scope from canonical thread detail. A new `personalWriteScope` capability gates both actual text/media producers. An absent capability or invalid context holds sending and retains editable draft text; neither producer silently falls back to an unbound send. Existing request/text-only, encryption, contact, family, membership, workspace and moderation policies remain authoritative on the server.

DM preserves that scope in its existing encrypted account journal. Retrying a saved command retains its original ID, content, reply, media and authority. Legacy or stale journal entries are not rebound to a replacement grant. The current transport rejects them before a server call. Grant changes recreate only the composer/outbox owner, preserving the conversation list, draft namespace and search/scroll instance. Composer retirement and a current hold both stop an old completed upload from enqueueing. The shared composer distinguishes unavailable sending from a full queue, including Marketplace.

Consumer retains the original captured scope on each attempt and checks live access before dispatch, after upload URL creation, after upload, and before publishing a late completion or clearing text/reply/attachment state. Composer keys include actor/thread/authority; the surrounding list stays stable. Outgoing rows are also scoped to actor and thread. DM's local draft hook now has revision-checked clearing, including identical-text edits, replacement scopes and closed composers.

A further lost-acknowledgement regression exposed an existing Consumer confirmation gap. Canonical history now returns the caller's own client command key, and the actual Consumer page removes a matching local optimistic copy only for that sender. Another participant's matching key cannot confirm it. The canonical direct history projection does not expose a peer's command key. DM's existing own-author confirmation remains in use.

This qualifies the captured context on primary composers, not all queued mutations or every policy reversal. Saved stale/legacy commands remain retained rather than silently sent. A dedicated review/recovery presentation is still required: in particular, an invalidated Consumer optimistic command can retain its pending presentation until canonical history confirms it, and DM's failed retained entries need a clearer explicit review journey. Do not treat these local send guards as complete recovery acceptance. Story reply, forwarding/edit/delete/reactions/typing and other producers retain their separate required audit/adoption work. Durable contact/family/request/thread-policy reversal qualification remains open.
