## Behavior

Consumer optimistic messages and DM personal/Marketplace queue entries now distinguish a held command from an ordinary retry. Missing/legacy or mismatched captured authority produces a neutral **Needs review** action. It does not display an endless pending tick or offer a retry that would silently rebind the command. A genuinely acknowledged message retains its sent state; canonical own-author confirmation continues to retire matching local copies.

Both clients use one EN/FR/AR review-copy and draft-composition contract. Review explains that the original may already have arrived and sends nothing. The user can copy its text into an empty draft, explicitly add it to an occupied draft, or keep it for later. Exact duplicate text is not added twice. The 8,000-character bound, current draft revision, active review identity and composer lifetime are checked. Another account/thread cannot inherit the review. Confirmation closes a review of the acknowledged command. A cold account query has a dedicated actual-page regression case.

Copying text does not mutate, delete, acknowledge or reauthorize the original queued command. DM updates the body of its existing encrypted account journal while preserving the original pending metadata and attachment. Existing retention/capacity policies remain in force. A storage error retains the source and surfaces through the existing local-save error state; the copy operation does not claim that it sent a message.

Attachments stay attached to the original command; review explicitly asks the user to inspect and reattach them if they choose to send again. Consumer optimistic presentations now retain the Blob and own/revoke their own presentation URL. Retiring the composer therefore cannot invalidate a queued image/file preview. Pending voice uses the existing voice component; video/file affordances use the retained local media. DM retains its existing media viewer and encrypted metadata. This qualifies availability of the retained local copy, not automatic media-command transfer to a new grant, storage expiry recovery or physical file access.

No local discard command or automatic resend was added. Explicit queue removal, broader resumable media recovery and all queued mutation/policy families remain separate required work. Consumer's optimistic media remains an in-memory presentation; this does not establish web process-kill recovery. The native journal/storage and actual device lifecycles retain their existing acceptance gates.
