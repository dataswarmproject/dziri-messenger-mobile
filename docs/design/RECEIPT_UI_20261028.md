# Exact receipt client integration

Connect Consumer and standalone to the same exact-message contract. Preserve current compact monochrome/rose-tick layout, typography, RTL, emoji-only UI and staff isolation. No provider/push activation, actual user initialization, production/schema release or real communications are authorized here.

Shared observation controller: exact incoming IDs, loaded-message delivery, 80% visibility with 500 ms active dwell for read, batches of at most 100, bounded retry delay, and immediate cancellation on background/offline/route/account/epoch changes. Manual inbox revision or sharing-generation changes must not automatically re-read the same visible messages; a fresh focus or re-entry can observe them again. Late responses cannot alter a newer scope. Exact commands bind expected actor, membership epoch, inbox revision and read-sharing generation so delayed mutations cannot apply to another identity or consent epoch.

Both client adapters must prepare and subscribe with their actor/thread binding, acknowledge before bootstrap completes only with a valid tracked scope, render per-message outgoing state without guessing read from a timestamp prefix, and display unread readiness honestly. Native Marketplace already sends explicit ID batches; retain its separate backend shape while applying shared lifecycle/dwell behavior. Older backends without the exact capability must not receive new endpoints or unsafe prefix acknowledgements. Unknown receipt state must never become read. Verification must distinguish actual component/browser behavior with synthetic adapters from live two-account/device proof.

## Local implementation and verified behavior

Consumer's actual conversation route and standalone's actual conversation/list now use the same checked receipt controller. They prepare and subscribe to an actor/thread-bound private summary, deliver exact eligible incoming IDs, observe visible incoming IDs after focused active dwell, and subscribe to the public state of visible persisted outgoing messages. Pending outbox messages keep their local status. The optional `exactReceipts: 1` capability gates these new calls; it has not been published to the backend. This slice covers non-request, non-E2EE personal DMs/groups. It does not qualify every Messenger lane.

The canonical command binds the expected actor, membership epoch, inbox revision and sharing generation. Prepared members cannot omit the identity binding, and a delayed read from an older sharing generation is rejected. Identity changes cancel old timers and responses in the shared controller. Both actual adapters also reject queued viewability callbacks from the previous screen/account. Native explicitly recomputes viewability through the installed FlashList API, preserving its list instance, scroll position and search jump rather than remounting the list when preparation completes. Manual unread or sharing changes do not immediately reread the same visible message. Unknown/private receipt state never creates a delivered/read claim.

Both inbox projections display a dot while a tracked unread ledger is initializing rather than presenting its placeholder as a numeric count. Consumer bubble activation no longer toggles twice on focus followed by click/Enter, so the compact individual timestamp stays visible when activated. Existing monochrome geometry, rose read ticks, fonts, emoji-only UI and staff separation are retained.

Legacy public-thread and salon joins now require an active real account before creating or reviving membership. Workspace public joins reuse the same current company/role/ownership authority as current messaging operations. The salon wrapper rejects frozen and company-scoped conversations. Denial leaves prior membership/receipt epoch intact. This closes those tested join bypasses; it does not certify every legacy reader, discovery policy, family enrollment or broader revocation lifecycle.
