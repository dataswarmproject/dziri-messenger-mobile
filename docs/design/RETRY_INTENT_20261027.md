# Canonical retry-intent integrity — local implementation slice

This slice addresses the remaining core reliability requirement. A client message ID must acknowledge the same immutable send intent in both Consumer and DM. Current text/media and Marketplace transactions only check the key's scope, so changed text, reply targets or attachments can be incorrectly acknowledged as sent. This is an acknowledgement-integrity bug, not evidence that a second message was written.

## Required behavior

- Bind new commands to a versioned server-computed SHA-256 of the normalized canonical payload, including destination, canonical buyer/seller side, type, text/reply/media/shared-content metadata. No client-supplied authorization identity or digest is trusted.
- Genuine retries acknowledge the committed row without rewriting messages, previews, receipts, activity or deleted content. Subsequent edits/deletion do not redefine the original command. A changed payload must fail clearly and must never create an additional message under the same key.
- Recheck current active account, membership/business scope, freeze/archive/read-only and direct-contact/request policy before acknowledging. An already committed pending introduction may be acknowledged without allowing a second introduction or exposing the recipient's private decline/spam decision.
- Keep hashes internal to message rendering DTOs. Use optional schema fields, no backfill, no provider or client dependency. For legacy rows without an immutable digest, only a still-unedited, undeleted matching payload can be verified; ambiguous legacy retries fail without resending.
- Preserve Story/forward command provenance and existing public response shapes. Unqualified E2EE/key transport remains outside this plaintext-command slice.

Only synthetic transaction tests are authorized. Backend source/schema publication and live cross-client acceptance remain held. Consumer also needs a corrected attachment-command producer, described below; the standalone producer already snapshots immutable outbox commands. No standalone runtime or APK change is needed, and the preceding Story-flow APK remains the latest private client package.

## Implemented locally

- `messaging/commandIdentity.ts` serializes versioned fixed-order canonical tuples, using Convex's value serializer so special floating-point values cannot collapse to an absent value. It computes the digest inside the transaction and checks exact intent identity on retries.
- Personal text/media commands now recheck canonical active account, membership/business grant, freeze/read-only, archive and direct-contact policy before acknowledgement. Pending-introduction acknowledgement is allowed only for the sender's actual committed `requestMessageId`; it never authorizes media, a different introduction or a recipient send.
- Marketplace binds the persisted buyer/seller side as well as the content, images, parent and shared/affiliate references. Current authenticated scope/permissions are checked before lookup. A person gaining seller membership cannot reinterpret an existing buyer command as a seller reply.
- The original digest survives later edits/deletion. Matching retries return the existing ID/timestamp without restoring content, rewriting previews, adding activity or duplicating messages. Changed body, media, metadata, destination or command kind fails. Sender namespaces remain separate.
- Story reactions and emoji replies have different command kinds; ordinary text cannot acknowledge a Story or forwarded command. Forward retries bind source, destination and inspected text, and recheck blocked peers/read-only destination policy. Existing Story expiry/access/moderation and deleted-message rejection remain stricter than ordinary committed-send acknowledgement.
- Two optional `clientCommandHash` string fields widen the existing personal/Marketplace message schemas. There is no new table/index, backfill, plaintext command copy or dependency. These digests are omitted from both clients' message-rendering DTOs. A command digest is not encryption or E2EE.
- Legacy unchanged text/media/Marketplace/forward rows can be compared against their still-verifiable payload. Edited/deleted legacy rows fail without resending because the original intent is unknowable. Legacy Story commands also fail because the old row cannot distinguish an emoji reply from a reaction; legacy catalogue-derived sticker metadata cannot reliably reconstruct the original media command. No inferred digest is backfilled.
- Consumer's attachment selection identity is now separate from its send-command identity. Changing a failed caption/reply target creates a new send ID; an explicit retry retains the original ID, reply and already-uploaded storage. Success clears only its own unchanged text/reply/attachment scope. An old acknowledgement cannot discard a newer attachment draft. No visual layout, language or domain behavior was changed.
