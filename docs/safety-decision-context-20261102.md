# Private Block/Unblock decision consistency

Standalone companion: the task and evidence paths below refer to the canonical monorepo; local machine receipts remain under the stated artifact directory.

Scope: close stale same-account confirmations across intervening private decisions in both personal clients. This is a prerequisite to the complete Marketplace source/grant-bound Block flow; it does not enable Marketplace Block or declare the full catalogue complete.

The authenticated actor remains the only authority. The client captures its original account/target and opens an explicit preparation mutation. Ordinary reads create no records. For an unblocked relationship, preparation allocates one private actor/target consistency row if necessary. For an existing block, its immutable row identity and decision version are the witness, requiring no private relationship allocation. The opaque key also binds the selected action and actor account/family revisions. A missing private row is never interpreted as durable zero evidence: erasure/recreation must retire old unblocked contexts. A legacy block's missing version starts at zero under its fixed, non-reusable block-row identity; this does not backfill any historical receipt or permission evidence.

Each actual own block/unblock and repeated block decision advances private consistency, including when a reverse block masks changes to shared effective contact authority. Another actor's private block/unblock must not change this key. Shared receipt/send authority remains governed by effective two-way access. No timestamps, messages, reverse-block details, target account revisions or business credentials enter the client token.

Fresh scoped commands require their expected account and current key; mismatch rejects before any write. Existing callers retain legacy behavior, so the new guarantee is explicitly limited to upgraded scoped commands. Ambiguous/corrupt/exhausted witnesses are never silently reset. Corrupt private metadata prevents a new scoped block, while a valid existing block witness still permits scoped unblock. A deleted/deleting target may be unblocked without recreating technical data. Every repeated block also advances optional `blockedUsers.decisionRevision`, so an old unblock cannot erase a later block decision even during pending erasure. That field is omitted from semantic block exports and blocked-list DTOs. Existing private rows may advance during erasure; missing rows must not be recreated. Both participant indexes are included in erasure, and private consistency rows are excluded from exports.

An accepted legacy no-op unblock retires an existing preparation but allocates no relationship if none exists. This prevents an older prepared block from overriding the newer unblock intention. Consistency remains private; shared contact authority is unchanged.

Both clients now prepare only on explicit opening, preserve the chosen block/unblock action, require the returned account/state/key to match, and submit that captured key. Cancel is available during preparation. Canceled, replaced, unmounted and earlier-account responses cannot reopen a dialog, unlock a newer request or replace its captured key. A committed component keyed by account and target owns session state; it avoids render-time ref mutation and effect-driven state resets. Consumer cancellation restores keyboard focus to the current trigger.
