# Account-bound Block and Unblock confirmations

Local follow-up to the November 2 production release. Marketplace Block remains disabled while its complete command and enforcement flow is qualified.

Consumer and DM now capture the signed-in account and chosen target when opening a Block or Unblock confirmation. The canonical safety query is keyed by the expected account, derives the actual actor from authentication and returns no state when that expectation no longer matches. Unknown or lagging ownership keeps the action unavailable. The blocked-list row is a display hint; it cannot replace this live account check.

Both clients use the same generated safety intent contract. Observed account changes, identity loss, target changes, inactive views and unmount retire the previous confirmation. A late response from an earlier account lifetime cannot close a new dialog, display a private error or unlock a newer request, including observed A-to-B-to-A transitions. Confirmation preserves the chosen block/unblock action across ordinary live block-state updates instead of silently reversing it.

The block and unblock mutations accept an optional `expectedActorId` consistency constraint and reject a different authenticated account before block/contact writes. Legacy callers retain their existing behavior; this does not add an ownership guarantee to older installed binaries. The compatible backend extension must publish before the new clients. A client with unavailable ownership metadata fails closed for this optional action.

Evidence: the original existing-component account-switch reproduction failed in both clients (Consumer 15 passing / one failing; DM 13 passing / one failing). Backend contract reproduction had two passing / two failing cases. Qualified backend coverage passes 148 tests across seven files. Broad UI coverage passes 1,043 Consumer tests across 121 files and 346 DM tests across 46 files, supplemented by 30 final action/lifetime cases per client. A StrictMode probe passed without needing a separate replay fix. One Consumer busy-button test selector was corrected to recognize its real “Saving…” label; production behavior was unchanged by that test correction. Backend/native types, native changed-file lint, 78 domain cases and consistency checks pass. Android/iOS/web export passes against 1,016 unchanged source inputs using the existing stable builder and synthetic backend.

These are local source/compiler/synthetic checks. No new APK, provider activation, live account action or deployment is part of this increment. The installed app and production release remain unchanged. Same-account command freshness across intervening block/unblock, account-state and Marketplace grant/contact cycles still needs the full server observation model; this account-binding increment does not close those gates. Continue that work before enabling Marketplace Block, then complete account-only Marketplace Delete and the remaining catalogue/device/two-account acceptance. Push stays HARD_DISABLED and staff credentials stay isolated.
